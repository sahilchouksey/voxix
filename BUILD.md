# Building voxix

This guide covers how to set up a development environment and build voxix from source across supported platforms.

## Prerequisites

- [Rust](https://rustup.rs/) (latest stable)
- [Bun](https://bun.sh/) package manager
- [CMake](https://cmake.org/download/) (must be on `PATH`):
  - **macOS**: `brew install cmake` or `xcode-select --install`
  - **Linux**: install with your system packages (see below)

### Platform-specific packages

#### Linux

Build essentials and the libraries voxix links against:

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install build-essential clang libclang-dev libevdev-dev libasound2-dev pkg-config libssl-dev libvulkan-dev vulkan-tools glslc spirv-headers glslang-tools libgtk-3-dev libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev libgtk-layer-shell0 libgtk-layer-shell-dev patchelf cmake

# Fedora/RHEL
sudo dnf groupinstall "Development Tools"
sudo dnf install alsa-lib-devel pkgconf openssl-devel vulkan-devel glslc \
  clang clang-devel libevdev-devel \
  spirv-headers-devel spirv-tools-devel glslang \
  gtk3-devel webkit2gtk4.1-devel libappindicator-gtk3-devel librsvg2-devel \
  gtk-layer-shell gtk-layer-shell-devel \
  cmake

# Arch Linux
sudo pacman -S base-devel clang libevdev shaderc spirv-headers glslang alsa-lib pkgconf openssl vulkan-devel \
  gtk3 webkit2gtk-4.1 libappindicator-gtk3 librsvg gtk-layer-shell \
  cmake
```

#### macOS

- Xcode command line tools plus CMake (above). The build uses Metal acceleration; no extra packages are needed.

#### Windows

- Visual Studio with the "Desktop development with C++" workload
- Vulkan development tooling for the GPU-accelerated builds

## Setup Instructions

### 1. Clone the repository and install dependencies

```bash
git clone https://github.com/sahilchouksey/voxix.git
cd voxix
bun install
```

The VAD model (`silero_vad_v4.onnx`), the GIGAAM vocabulary, notification sounds, and tray images are committed under `core/resources/` together with the repo, so a fresh checkout has everything the app bundles. Additional transcription models are downloaded at runtime from the voxix model catalog.

### 2. Start the development server

```bash
bun run tauri dev
```

If `cmake` reports an unsupported policy on macOS, prefix the command:

```bash
CMAKE_POLICY_VERSION_MINIMUM=3.5 bun run tauri dev
```

Frontend-only iteration also works:

```bash
bun run dev      # Vite dev server
bun run build    # TypeScript + Vite production build
bun run preview  # Preview built frontend
```

### 3. Production build

```bash
bun run tauri build
```

Build outputs land under `core/target/`:

- Linux bundles: `deb`, `rpm`, `AppImage`
- macOS: `.app` bundle in `.dmg`
- Windows: `.exe` installer (NSIS)

## Running the packaged app

The raw binary (`core/target/release/voxix`) expects the bundled resources and transcription libraries next to it, so prefer the produced bundles directly on Linux:

```bash
bun run tauri build --bundles deb -- --no-default-features
bun run install:deb   # installs the deb from core/target/release/bundle/deb/
```

The deb and rpm place the app's transcription libraries into the app-private `/usr/lib/voxix` directory that is on the binary's rpath, so no `ldconfig` step is needed. The AppImage carries the same libraries inside the image. These mappings live in `core/tauri.conf.json` and are linked up by the rpath set in `core/build.rs`.

## Development workflow

```bash
bun run lint            # ESLint for the frontend
bun run format          # Prettier + cargo fmt
bun run format:check    # Both formatters, check-only

bunx tsc --noEmit       # Frontend type check
bun run check:translations  # Locale key parity against en

cargo check --manifest-path core/Cargo.toml --all-targets
cargo test  --manifest-path core/Cargo.toml --all-targets
```

Auto-generated artifacts you should never hand-edit:

- `ui/bindings.ts` — regenerated by the Rust backend from the Tauri/Specta commands in debug builds.
- `core/src/catalog/catalog.json` — hand-maintained; was hand-pruned to the mirrored set in commit 77874fe. Do NOT run scripts/gen_catalog.py to regenerate it — that would restore ~212 artifact entries that are not hosted anywhere. Extend it only by explicit owner instruction.
- `bun.lock` and `core/Cargo.lock` — regenerated by `bun install` / `cargo` respectively.

## Troubleshooting

### `cmake` minimum version errors (macOS)

Some toolchain plugins require CMake ≥ 3.5 policies; run:

```bash
CMAKE_POLICY_VERSION_MINIMUM=3.5 bun run tauri dev
```

### Linux: missing webview or audio libraries

A start failure with `error while loading shared libraries: libwebkit2gtk-...` or `libasound...` means the platform packages from the prerequisites section are not all installed.

### Windows build fails with path-limit errors (MSB3491/FTK1011/MSB6003)

Older per-user checkouts may hit Windows MAX_PATH limits. Move the repository closer to the drive root (e.g. `C:\voxix`) and rebuild.

### Vulkan/GPU output missing on Linux

Install the Vulkan SDK candidates listed above and verify with `vulkaninfo`. Whisper-family models fall back to CPU when no usable Vulkan device is found.
